# Transaction Cost Analysis (TCA)

> Measure execution quality from order, fill, quote and bar data, and say how far each number can be trusted.

**Status:** MVP implemented and tested. Simulated data only.  
**Stack:** Python 3.12, FastAPI, SQLite, `Decimal` arithmetic, Prometheus client, vanilla-JS dashboard with hand-drawn SVG charts  
**Original build specification:** [docs/blueprint.md](docs/blueprint.md)

The service explains why an order cost more or less than a benchmark. Benchmark choice and
market-data timing are explicit: every figure names its benchmark, every benchmark is taken
strictly point-in-time, and anything measured against missing, stale or clock-skewed data
is flagged and kept out of the headline numbers.

There is no market or broker connectivity in this repository. All prices are generated by
a seeded simulator; no figure here describes a real venue, broker or strategy.

## Quickstart

Requires Python 3.12+.

```bash
make setup              # create .venv, install dependencies
make demo               # terminal walkthrough on the fixture, including failure cases
make run                # API + dashboard at http://127.0.0.1:8009  (OpenAPI at /docs)
```

`make run` loads the simulated fixture in `examples/data` (61 parent orders, 310 fills,
14,451 quotes across three venues, 266 one-minute bars). In the dashboard, switch the
benchmark and grouping, then click an order: `P0001` arrived before any quote existed,
`P0036` arrived during a quote outage, `P0055` was measured against a venue whose clock was
1.8 seconds out.

```bash
make lint               # ruff check + format check
make test               # unit tests
make integration-test   # store, API, CLI, failure scenarios and replay
make reconcile          # recompute the committed report from raw CSVs, without the tca package
make report             # write a report bundle to reports/latest
```

`examples/walkthrough.sh` loads the small hand-checkable example over curl.

The Makefile sets `PYTHONPATH=src`. Set it yourself when calling `python -m tca` directly.

## How it works

```text
orders + child orders + fills        quotes + bars
              |                            |
              +-------- importer ----------+    row-level validation, rejects with reasons
                          |
                        store                   idempotent writes, content-hash versions
                          |
               point-in-time alignment          consolidated quote as of each instant,
                          |                     never a later one
                 benchmark calculations         arrival mid, decision mid, interval VWAP,
                          |                     each with status ok / degraded / missing
              cost attribution + aggregation    signed costs, spread/drift split, fees;
                          |                     groups use trusted orders only
          dashboard / API / CSV report bundle   every output carries methodology + dataset version
```

The rules that matter:

- **One sign convention.** `cost = side_sign x (execution price - benchmark) x quantity`.
  Positive always means worse than the benchmark, for buys and sells.
- **No look-ahead.** A benchmark uses quotes stamped at or before its instant. If there are
  none it has no value and the order is flagged. It is never backfilled from later data.
- **Trusted or not.** A benchmark that exists but rests on a stale, crossed or clock-skewed
  quote is shown and marked `degraded`. Group figures leave such orders out by default and
  report how many were left out.
- **Parts add up.** All basis points use the benchmark notional as denominator, so
  spread + drift = shortfall and shortfall + fees = all-in, exactly.
- **Reproducible.** A report contains no wall-clock time. Same inputs and methodology give
  byte-identical files.

Formulas, flags and a fully worked example are in [docs/methodology.md](docs/methodology.md).
Design and the invariant-to-test map are in [docs/architecture.md](docs/architecture.md).
The hardest trade-off, what to do with an order whose arrival quote is missing or doubtful,
is written up in
[ADR 0001](docs/decisions/0001-point-in-time-benchmarks-flag-do-not-backfill.md).
Operations are in [docs/runbook.md](docs/runbook.md).

## API

No authentication; the server binds to loopback by default.

```text
POST /v1/imports/{orders|child-orders|fills|quotes|bars}   CSV body, or JSON {"rows": [...]}
GET  /v1/datasets                       row counts, content versions, recent imports, orphan fills
GET  /v1/methodology                    version id, parameters, sign convention, rounding
GET  /v1/tca/orders                     one row per order; filters below
GET  /v1/tca/orders/{order_id}?benchmark=arrival_mid|decision_mid|interval_vwap
GET  /v1/tca/orders/{order_id}/overlay  quote path, bars, fills and benchmark levels for the chart
GET  /v1/tca/summary?group_by=all|broker|symbol|strategy|side|venue|time_bucket
                    &benchmark=...&include_untrusted=false&bucket_minutes=30
GET  /v1/tca/summary.csv                same parameters
GET  /v1/tca/export.csv?view=orders|fills|benchmarks
GET  /metrics | /healthz
```

Filters on the `tca` endpoints: `symbol`, `broker`, `strategy`, `side`, `venue`, and
`start` / `end` on arrival time (ISO-8601 with offset).

An import returns `200` with `accepted`, `duplicates`, `rejected` and per-row reject
reasons; a payload with the wrong columns is refused whole with `400`. Money, prices and
basis points are serialised as fixed-point decimal strings. A figure that cannot be
computed is `null` (blank in CSV), never zero.

## Definition of done

| Requirement | Evidence |
|---|---|
| Signed shortfall is positive for unfavourable fills for both buys and sells | [tests/scenarios/test_definition_of_done.py](tests/scenarios/test_definition_of_done.py), section 1: bad and good fills on both sides against all three benchmarks; buy and sell costs do not net; fixture signs checked against an independent reading of the raw files |
| Missing arrival quotes are flagged instead of backfilled from future data | Section 2: a quote one microsecond after arrival is ignored, further late quotes change nothing, the order is exported blank and left out of aggregates with `null` rather than `0` |
| Report output includes benchmark methodology and dataset versions | Section 3: manifest, every order and benchmark row, and API responses; changing data or a threshold changes the stated version |
| Sample calculations reconcile manually within rounding tolerance | Section 4: every fixture order and the headline aggregate recomputed with `fractions.Fraction` from the raw CSVs; the worked example in [docs/methodology.md](docs/methodology.md) asserted digit for digit. [scripts/reconcile.py](scripts/reconcile.py) does the same from the command line |

Failure scenarios from the blueprint's test strategy (missing data, clock skew, stale
events, connection loss and recovery, duplicate delivery, rejected writes, out-of-order
delivery, restart) are in
[tests/scenarios/test_data_quality.py](tests/scenarios/test_data_quality.py). Replay
(seeded fixture and a committed golden report reproduced byte for byte) is in
[tests/scenarios/test_replay.py](tests/scenarios/test_replay.py).

Latest local run: 200 tests passing (107 unit, 93 integration and scenario) on Python 3.12,
macOS, in a virtualenv built from the declared dependencies. No performance benchmarks have been
run, so none are reported.

### Differences from the original blueprint

- **`Decimal` and SQLite, not Polars/Pandas and DuckDB/ClickHouse.** The blueprint asks for
  fixed-point money and results that reconcile by hand; exact decimals end to end make that
  straightforward. The cost is speed: the analysis is plain Python over in-memory records.
- **Plain HTML/JS with hand-drawn SVG, not Plotly/React.** No build step and no scripts
  loaded from a CDN.
- **One process**, with the blueprint's five services as modules.
- **Extra input: child orders.** Needed for a per-venue fill rate. Optional.
- **Extra benchmark: decision mid**, alongside arrival mid and interval VWAP.
- **"Market impact" is not reported.** What the data supports is the mid's drift between
  arrival and each fill, which mixes the order's own impact with unrelated market movement.
  It is labelled drift, and the dashboard says the two are not separable.

### Planned / not done

- Order-difficulty normalisation (size against volume, spread, volatility) so that venue,
  broker and strategy rows can be compared fairly. Until then every grouped view carries a
  warning not to rank on it.
- Time-weighted interval VWAP and VWAP from trade prints instead of bars.
- Opportunity cost for unfilled quantity.
- Applying corrections and busts. Today a restated row under an existing key is rejected.
- Incremental analysis and a columnar store for multi-day data; load testing and a
  benchmark methodology.
- Authentication and per-user access.
- Comparison of simulator execution strategies as an experiment (blueprint week 5+), and
  the link to the Smart Order Router project. The fixture has four strategies, but they
  receive different orders, so their rows are not a controlled comparison.
- Currency handling. All amounts are assumed to be in one currency.

### Not verified

- The Docker image and compose file have not been built here.
- The CI workflow has not run on GitHub.
- The dashboard was loaded in a browser against the fixture and its summary, order list
  and drill-down were checked by eye. A later change to the position of the "decision" and
  "arrival" labels on the drill-down chart was not re-checked in a browser. There are no
  automated browser tests.
- The test suite emits a deprecation warning from Starlette's test client about `httpx`.
  The declared dev dependency is still `httpx`.

## Explicit non-goals

- Claiming causal market impact from only coarse bars.
- Comparing venue performance without normalising order difficulty.
- Mixing buy and sell signed costs incorrectly.

## Safety, data and operational boundaries

- **Simulated data only.** No real-money, broker or market-data connectivity exists in this
  repository, and there are no credentials to configure.
- The API has no authentication. It binds to `127.0.0.1` by default and the compose file
  publishes on loopback only.
- Money and prices use `Decimal` from parsing to output; quantities are whole shares. The
  only floats are the Prometheus gauges.
- Imported text is rendered in the dashboard as text, never as HTML.
- Before loading real data: comply with market-data licences and broker terms, and treat
  order and fill history as confidential.
- No strategy, broker or venue performance is implied by any figure here.
